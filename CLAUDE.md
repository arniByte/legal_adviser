# Контекст для агентов

Репозиторий — решение кейса ПСБ «Юридический ассистент» (Hack&Change 2026). Дедлайн сдачи — **15 ноября 2026**.

Прежде чем что-то менять, прочитай по порядку:

1. `docs/STATE.md` — что сделано, что проверено, что осталось. **Обновляй его в конце каждой сессии.**
2. `docs/CASE_BRIEF.md` — факты из кейса и техрегламента: оценка, правила, база знаний, ловушки.
3. `docs/SUBMISSION_GUIDE.md` — как сдавать сабмиты и финальный комплект.
4. `docs/DECISIONS.md` — принятые решения и причины. Новое решение — новая строка.

## Жёсткие правила (из техрегламента, нарушать нельзя)

- В ZIP уходят только файлы из `submission/`, **плоско**: `solution.py`, модули `la_*.py`, `requirements.txt`. Никаких подпапок и пакетов.
- В `submission/requirements.txt` — только строки из `materials/requirements.txt`, с теми же версиями. Сейчас это `httpx` и `numpy`; не добавляй зависимости без необходимости.
- Никаких `pip install` из кода, никаких внешних источников фактов, никаких ключей в коде, файлах и логах.
- Модели и адрес API — только из переменных окружения (`LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `EMB_MODEL`, `RERANKER_MODEL`).
- `solution.py` обязан оставить валидный `submission.csv` (`id,answer`, все id, непустые ответы) при любых сбоях и уложиться в 20 минут.
- В логи сабмита — только агрегаты. Тексты скрытых вопросов и ответы не логировать.
- Ответ ассистента опирается только на базу знаний. Знания модели о законах использовать нельзя: нормы в базе новее и местами отличаются.

## Архитектурные инварианты

- **Одно ядро.** `app/` — тонкий HTTP-слой над `submission/la_*.py`. Логику поиска, генерации и проверки в `app/` не дублировать.
- **Ничего не привязано к именам файлов базы.** Индекс и реестр строятся при запуске из архива; правила работают от структуры и размера документов.
- **Проверка фактов — кодом** (`la_verify.py`), а не второй моделью. Эталоны из `eval/devset.jsonl` и демо-ответы организаторов обязаны проходить её без замечаний — на это есть тест.
- Примеры в системном промпте подключаются, только если их документы есть в загруженной базе.

## Команды

```bash
uv venv .venv && uv pip install --python .venv/bin/python -r requirements.txt pytest
.venv/bin/python -m pytest -q tests                  # 31 тест, без сети
.venv/bin/python scripts/build_submission.py --smoke # собрать dist/submission.zip и прогнать на заглушке
.venv/bin/python scripts/mock_llm.py --port 8765 --recorded --replay   # заглушка API
LLM_BASE_URL=http://127.0.0.1:8765/v1 LLM_API_KEY=mock .venv/bin/python -m uvicorn app.server:app --port 8000
.venv/bin/python eval/run_eval.py --workers 2        # нужен настоящий ключ: ответы, baseline, судья, отчёт
```

Заглушка `scripts/mock_llm.py` — не модель: по умолчанию она отвечает выдержкой из контекста. Флаг `--recorded` воспроизводит ответы, записанные с настоящей модели (`eval/recorded_answers.json`), `--replay` — эталонные выводы примеров из промпта.

## Как менять промпт и конвейер

1. Правка в `submission/la_prompts.py` или `la_pipeline.py`.
2. `pytest` и `build_submission.py --smoke`.
3. С ключом: `eval/run_eval.py`, смотреть раздел «Что смотреть в первую очередь» в отчёте.
4. Запись в `docs/STATE.md` (журнал сабмитов) и, если решение принципиальное, в `docs/DECISIONS.md`.

## Чего не делать

- Не подгонять решение под 18 демо-вопросов и не вшивать ответы.
- Не добавлять LangChain, векторные БД и прочие тяжёлые зависимости: фрагментов сотни.
- Не выдавать ответы заглушки или эталоны за ответы модели — ни в отчётах, ни в презентации.
- Не раздувать ответ: в сабмит идёт только блок `<answer>`; смежные нормы модель пишет в `<extra>`, он виден только в веб-чате.
- Не коммитить `.env`, `dist/`, `eval/runs/`.
