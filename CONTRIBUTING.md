# Разработка

## Окружение

```bash
uv venv .venv
uv pip install --python .venv/bin/python -r requirements.txt pytest
cp .env.example .env    # для запуска с настоящей моделью
```

Python 3.10+. Docker нужен только для проверки финальной сборки.

## Структура

| Каталог | Что внутри |
|---|---|
| `submission/` | ядро ассистента и `solution.py` — всё, что уходит в ZIP на автопроверку |
| `app/` | веб-прототип: HTTP-слой над ядром и статический интерфейс |
| `eval/` | набор вопросов с эталонами, локальный судья, записанные ответы модели |
| `scripts/` | сборка ZIP, заглушка API |
| `tests/` | автотесты |
| `data/` | материалы организаторов: база знаний, демо-вопросы, разрешённые зависимости, пример сабмита |
| `docs/` | кейс, архитектура, оценка, решения |
| `presentation/` | презентация, иллюстрации для README и общий стиль `theme.css` |

## Команды

```bash
.venv/bin/python -m pytest -q tests                    # автотесты, без сети и ключей
.venv/bin/python scripts/build_submission.py --smoke   # собрать dist/submission.zip и прогнать его на заглушке API
.venv/bin/python eval/run_eval.py --workers 6          # локальная оценка, нужен ключ в окружении
node presentation/build.js                             # PDF презентации и иллюстрации README (нужен Playwright)
node presentation/build.js --shots                     # плюс свежие скриншоты интерфейса; веб-прототип должен работать на :8000
```

Веб-прототип без Docker:

```bash
set -a; . ./.env; set +a
.venv/bin/python -m uvicorn app.server:app --port 8000
```

Без ключа подойдёт заглушка API: она воспроизводит ответы, записанные с настоящей модели.

```bash
.venv/bin/python scripts/mock_llm.py --port 8765 --recorded --replay &
LLM_BASE_URL=http://127.0.0.1:8765/v1 LLM_API_KEY=mock .venv/bin/python -m uvicorn app.server:app --port 8000
```

## Правила

Требования регламента автопроверки — нарушение любого из них обнуляет сабмит:

- В ZIP уходят только файлы из `submission/`, без вложенных папок: `solution.py`, модули `la_*.py`, `requirements.txt`.
- В `submission/requirements.txt` — только строки из `data/allowed_requirements.txt`. Сейчас это `httpx` и `numpy`.
- Никаких `pip install` из кода и никаких ключей в коде, файлах и логах.
- Адрес API и модели берутся только из переменных окружения.
- `solution.py` оставляет валидный `submission.csv` при любом сбое и укладывается в 20 минут.
- В лог сабмита пишутся только агрегаты, без текстов вопросов и ответов.

Принципы решения:

- **Одно ядро.** `app/` не дублирует поиск, генерацию и проверку — только вызывает `submission/la_*.py`.
- **Ничего не привязано к именам файлов базы.** Индекс и реестр строятся при запуске из архива.
- **Факты проверяются кодом.** Эталоны из `eval/devset.jsonl` и демо-ответы организаторов проходят `la_verify.py` без замечаний — это закреплено тестом.
- **Ответ — строго на вопрос.** Судья видит только блок `<answer>`; смежные положения модель пишет в `<extra>`, их показывает веб-чат.
- **Только база знаний.** Знания модели о законах не используются: нормы в базе новее и местами отличаются.

## Изменение промпта и конвейера

1. Правка в `submission/la_prompts.py` или `submission/la_pipeline.py`.
2. `pytest` и `build_submission.py --smoke`.
3. `eval/run_eval.py` — сравнить Score и посмотреть раздел «Что смотреть в первую очередь» в отчёте `eval/runs/<метка>/report.md`.
4. Новая строка в журнале сабмитов в [`docs/evaluation.md`](docs/evaluation.md); принципиальное решение — в [`docs/decisions.md`](docs/decisions.md).

## Отправка сабмита

Собрать архив: `python scripts/build_submission.py --smoke`. Загрузить `dist/submission.zip` на платформе. Строку результата внести в журнал в `docs/evaluation.md`.

Решение пишет в stderr диагностику: переданные переменные окружения (только имена секретов), состав каталога с данными, отпечаток базы знаний (у публичной — `3a0ecc1217a91cae`), число вопросов, режимы обработки, время на вопрос, длину ответов, ошибки API.

## Стиль

- Python: стандартная библиотека плюс `httpx` и `numpy` в ядре, FastAPI в прототипе. Комментарии объясняют «почему», а не «что».
- Коммиты: короткий заголовок в повелительном наклонении, тело — зачем изменение и как проверено.
- Документация — по-русски, без воды: факт, источник, вывод.
- Интерфейс, презентация и иллюстрации — в одном стиле: светлый фон, стекло, переливающаяся сфера, шрифт Onest, крупный текст без мелких подписей. Цвета и шрифты — в `app/static/app.css` и `presentation/theme.css`.
