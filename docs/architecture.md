# Архитектура

Одно ядро (`submission/la_*.py`) обслуживает и пакетную автопроверку (`submission/solution.py`), и веб-прототип (`app/`). Ниже — путь вопроса через систему и устройство каждого этапа.

```
вопрос или диалог
  │
  ├─ 1. разбор диалога          код        реплики, последняя реплика пользователя, вставки «Система:»
  ├─ 2. подсказки реестра       код        контрагент, похожие названия, номер договора, редакция на дату
  ├─ 3. контекст                код + API  BM25 + bge-m3 → слияние рангов → реранкер; малые документы целиком
  ├─ 4. ответ                   модель     один вызов: разбор, статус, ответ, смежные положения, источники
  ├─ 5. расширенный поиск       модель     только перед отказом или частичным ответом
  └─ 6. проверка                код        ссылки, цитаты, числа, даты, названия → одно исправление при ошибке
```

## База знаний — `la_kb.py`

**Загрузка.** Архив или каталог с TXT, MD и DOCX. Категория документа определяется по префиксу имени файла, а без него — по шапке справочной системы. Индекс строится при каждом запуске: решение не привязано к конкретному набору файлов.

**Очистка.** Строка, адресованная ИИ и содержащая указание («игнорируй», «отвечай», «не упоминай»), заменяется служебной пометкой. В публичной базе таких строк одна — в служебной записке. Детектор требует одновременно обращения к ассистенту и императива, поэтому не срабатывает на обычный юридический текст; это закреплено тестом.

**Структура.** Документ разбирается на единицы с адресом и позицией в тексте:

- договоры и регламенты — на пункты `п. 3.1` с названием раздела;
- законы с нумерацией — на пункты, подпункты и примечания (`п. 1, подп. 2.1`); подпункт хранит вводную часть своего пункта, иначе непонятно, к какой ставке он относится;
- законы без нумерации (ТК) — на части по абзацам; перечни после двоеточия остаются в своей части;
- редакционные пометки справочной системы («Пункт 3 изменен с 1 января 2026 г.») отделяются от текста и привязываются к своей единице как примечание.

**Реестр.** Из шапок извлекаются номер документа, дата, стороны, редакция и срок её действия, связь допсоглашения с договором. Контрагенты объединяются по основе названия; для каждого находятся «двойники» — названия, которые легко спутать.

## Поиск и контекст — `la_retrieval.py`

- **BM25** по фрагментам с лёгким русским стеммером и раскрытием сокращений (`НДС`, `МРОТ`, `УПД`). Морфологических библиотек в разрешённом списке нет.
- **Векторы bge-m3** через API. Фрагменты базы векторизуются один раз и кешируются по отпечатку базы; вопросы пакетного прогона — одним батчем.
- **Слияние рангов** (reciprocal rank fusion) и **реранкер** Qwen3 Reranker 8B для верхних 24 кандидатов.
- Эмбеддинги и реранкер необязательны: при их отказе поиск остаётся полнотекстовым.

**Контекст** собирается по размеру, а не по именам файлов. Документы компании (вместе 16 тыс. знаков) подаются целиком всегда. Закон до 9 тыс. знаков — целиком, большой — лучшими фрагментами в порядке текста, вместе со вводной частью пункта, соседними частями длинной единицы и общим правилом в начале статьи. Закон попадает в контекст, только если его фрагмент оказался в верхней части общего рейтинга, поэтому вопросы о договорах не тянут налоговые статьи.

## Ответ — `la_pipeline.py`, `la_prompts.py`

**Подсказки реестра** вычисляются кодом и передаются модели отдельным блоком:

- какой контрагент упомянут и какие у него документы; с кем его не путать;
- название подходит нескольким контрагентам — ответить по каждому и попросить уточнить;
- номер или наименование из вопроса в базе отсутствует;
- на дату или период события какая редакция действовала, какая ещё нет; законы даны только в действующей редакции.

**Диалог.** Поле вопроса разбирается на реплики. Ответ строится на последнюю реплику пользователя; реплики ассистента из истории и вставки «Система:» передаются модели как недоверенные данные.

**Вызов модели** один. Вывод — пять блоков: `<analysis>`, `<status>`, `<answer>`, `<extra>`, `<sources>`. В сабмит идёт только `<answer>`: прямой ответ на вопрос, обычно 1–2 предложения. Смежные положения, о которых не спрашивали, модель пишет в `<extra>` — их показывает веб-чат. Статус — одно из `ANSWER`, `PARTIAL`, `NOT_IN_KB`, `OFF_TOPIC`, `ILLEGAL`, `ROLE`.

**Расширенный поиск.** Если статус `NOT_IN_KB`, `PARTIAL` или `ILLEGAL`, контекст расширяется (больше фрагментов, все малые статьи законов целиком) и модель отвечает повторно. Ложный отказ для судьи — такое же поражение, как выдуманный факт.

**Страховочный предел** длины: ответ длиннее 90 слов (140 для перечня шагов и расчётов) сохраняет начальные предложения и ссылку на источник, остальное переносится в смежные положения.

## Проверка — `la_verify.py`

После генерации ответ сверяется с документами, которые видела модель:

- документ и пункт из каждой ссылки существуют, цитата находится в тексте (с допуском на пересказ);
- каждое число, сумма, процент, срок и дата есть в документах или в вопросе; разные записи одного значения — «450 000», «450 тыс.», «четыреста пятьдесят тысяч» — считаются одним;
- число, которого нет в тексте, допустимо, если оно получается арифметикой из чисел документа и вопроса, в том числе в несколько шагов;
- названия в кавычках и номера документов встречаются в базе.

При ошибке модель получает перечень замечаний и одну попытку исправить ответ. Смежные положения показываются, только если в них нет ни одного неподтверждённого факта.

Проверка сделана кодом, а не второй моделью: она детерминирована, работает за миллисекунды и не может согласиться с ошибкой. Ложных срабатываний на эталонах нет — это закреплено тестом.

## Пакетный прогон — `solution.py`

- `submission.csv` с безопасными ответами-заглушками пишется до первого обращения к API и перезаписывается по мере готовности.
- Бюджет времени (по умолчанию 16 минут из 20) распределяется по вопросам: полный режим → облегчённый (без реранкера, второго прохода и исправления) → заглушка. Сторожевой таймер записывает файл и завершает процесс до лимита платформы.
- Повторы при 429, 5xx и тайм-аутах ограничены, с паузой. Параллельность — из `MAX_WORKERS`.
- В stderr — только агрегаты: число вопросов, режимы, статусы, время, длина ответов, ошибки API.

## Веб-прототип — `app/`

FastAPI-сервер (`app/server.py`) превращает диалог в чате в тот же формат, что получает автопроверка, и вызывает ядро. Потоковый эндпоинт `/api/chat/stream` сообщает этапы обработки. Интерфейс (`app/static/`) — HTML, CSS и JavaScript без сборки; шрифты подключены локально.

База знаний показана кластером клеток: одна клетка — один документ, площадь — объём текста (`app/cells.py`). Документы, на которые сослался ответ, подсвечиваются; утратившая силу редакция приглушена. Клик по источнику открывает полный текст документа с подсвеченным положением.

| Эндпоинт | Назначение |
|---|---|
| `GET /api/health` | состояние: модель, режим поиска, размер базы |
| `GET /api/documents` | список документов с раскладкой клеток |
| `GET /api/documents/{id}` | полный текст документа и его разметка |
| `POST /api/chat` | ответ целиком |
| `POST /api/chat/stream` | ответ с этапами обработки (server-sent events) |
