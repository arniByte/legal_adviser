# Решения

Одна строка — одно решение: что решили и почему. Новые добавляются в конец.

| № | Решение | Почему |
|---|---|---|
| 1 | Документы компании подаются модели целиком в каждом запросе | их 8, вместе 16 тыс. знаков (около 6 тыс. токенов); на демо простой поиск ставил нужный документ первым только в 12 случаях из 17. Заодно модель видит обе редакции и допсоглашение сразу |
| 2 | Разбиение по структуре (пункты, части, подпункты), а не по длине | ссылку на пункт можно проверить и подсветить; подпункт НК ст. 164 без вводной части пункта не сообщает ставку |
| 3 | Примечания справочной системы («изменен с …») отделены от текста норм | по ним определяется, что нужной редакции закона в базе нет; в тексте нормы они мешают поиску |
| 4 | Свой BM25 и свой лёгкий стеммер, без библиотек | в разрешённом списке нет русской морфологии; сотни фрагментов не требуют векторной БД |
| 5 | Эмбеддинги и реранкер — необязательные слои | при отказе API поиск остаётся полнотекстовым, прогон не падает |
| 6 | Один вызов модели на вопрос; второй — только перед отказом, частичным ответом или отказом по противоправному запросу | скорость и лимит 20 минут; отказ при наличии ответа — поражение, поэтому перед ним контекст расширяется |
| 7 | Проверка ответа кодом, а не второй моделью | детерминирована, мгновенна, не «соглашается» с ошибкой; выдуманный факт обнуляет вопрос |
| 8 | Проверяются числа, даты, названия в кавычках, номера документов, ссылки и цитаты; расчёты — арифметически | это ровно то, из чего состоит выдуманный факт; на 71 реальном ответе после настройки ложных срабатываний нет |
| 9 | Неточная метка источника при найденной цитате — замечание, а не ошибка | иначе тратится лишний вызов модели на «исправление» верного ответа |
| 10 | Строки-инструкции для ИИ вырезаются из документов при загрузке | в служебной записке зашита команда отвечать «90 дней»; вторая линия защиты — проверка чисел |
| 11 | Подсказки реестра (контрагент, двойники, номер, редакция на дату) считает код | это вычислимо без модели и снимает самые дорогие ошибки: не тот контрагент, не та редакция |
| 12 | Вопрос, история и «системные» вставки передаются как недоверенные данные в одном сообщении пользователя | поддельные роли не получают полномочий; реплики ассистента из истории перепроверяются |
| 13 | Формат вывода модели — простые теги, разбор терпит отклонения | строгий JSON-режим через прокси не гарантирован |
| 14 | Индекс строится при запуске, готовый индекс в ZIP не кладём | база на платформе может отличаться; неясно, переносятся ли не-`.py` файлы; расчёт занимает секунды |
| 15 | `temperature = 0` независимо от настроек задачи | ответы должны быть буквальными и воспроизводимыми |
| 16 | `submission.csv` пишется до первого вызова API и дописывается по ходу; есть бюджет времени и сторожевой таймер | пустой или отсутствующий файл обнуляет сабмит целиком |
| 17 | Веб-прототип — тонкий слой над ядром сабмита, фронтенд без сборки | одинаковое поведение в сабмите и на демонстрации; один образ, одна команда запуска |
| 18 | В логи сабмита идут только агрегаты | вытаскивать скрытые вопросы через логи нечестно и бесполезно для private-части |
| 19 | Стиль ответа: 1–3 предложения, прямой ответ первым, пункт в скобках | так написаны эталоны организаторов (24–60 слов); лишняя фраза — лишний риск |
| 20 | Примеры в промпте подключаются только при наличии их документов в базе | промпт не должен упоминать документы, которых модель не видит |
