# Решения

Ключевые решения и их причины. Новые добавляются в конец таблицы.

| № | Решение | Почему |
|---|---|---|
| 1 | Документы компании подаются модели целиком в каждом запросе | их 8, вместе 16 тыс. знаков (около 6 тыс. токенов); на демо простой поиск ставил нужный документ первым только в 12 случаях из 17. Заодно модель видит обе редакции и допсоглашение сразу |
| 2 | Разбиение по структуре (пункты, части, подпункты), а не по длине | ссылку на пункт можно проверить и подсветить; подпункт НК ст. 164 без вводной части пункта не сообщает ставку |
| 3 | Примечания справочной системы («изменен с …») отделены от текста норм | по ним определяется, что нужной редакции закона в базе нет; в тексте нормы они мешают поиску |
| 4 | Свой BM25 и свой лёгкий стеммер, без библиотек | в разрешённом списке нет русской морфологии; сотни фрагментов не требуют векторной БД |
| 5 | Эмбеддинги и реранкер — необязательные слои | при отказе API поиск остаётся полнотекстовым, прогон не падает |
| 6 | Один вызов модели на вопрос; второй — только перед отказом, частичным ответом или отказом по противоправному запросу | скорость и лимит 20 минут; отказ при наличии ответа — поражение, поэтому перед ним контекст расширяется |
| 7 | Проверка ответа кодом, а не второй моделью | детерминирована, мгновенна, не «соглашается» с ошибкой; выдуманный факт обнуляет вопрос |
| 8 | Проверяются числа, даты, названия в кавычках, номера документов, ссылки и цитаты; расчёты — арифметически | это ровно то, из чего состоит выдуманный факт; на 71 реальном ответе после настройки ложных срабатываний нет |
| 9 | Неточная метка источника при найденной цитате — замечание, а не ошибка | иначе тратится лишний вызов модели на «исправление» верного ответа |
| 10 | Строки-инструкции для ИИ вырезаются из документов при загрузке | в служебной записке зашита команда отвечать «90 дней»; вторая линия защиты — проверка чисел |
| 11 | Подсказки реестра (контрагент, двойники, номер, редакция на дату) считает код | это вычислимо без модели и снимает самые дорогие ошибки: не тот контрагент, не та редакция |
| 12 | Вопрос, история и «системные» вставки передаются как недоверенные данные в одном сообщении пользователя | поддельные роли не получают полномочий; реплики ассистента из истории перепроверяются |
| 13 | Формат вывода модели — простые теги, разбор терпит отклонения | строгий JSON-режим через прокси не гарантирован |
| 14 | Индекс строится при запуске, готовый индекс в ZIP не кладём | база на платформе может отличаться; неясно, переносятся ли не-`.py` файлы; расчёт занимает секунды |
| 15 | `temperature = 0` независимо от настроек задачи | ответы должны быть буквальными и воспроизводимыми |
| 16 | `submission.csv` пишется до первого вызова API и дописывается по ходу; есть бюджет времени и сторожевой таймер | пустой или отсутствующий файл обнуляет сабмит целиком |
| 17 | Веб-прототип — тонкий слой над ядром сабмита, фронтенд без сборки | одинаковое поведение в сабмите и на демонстрации; один образ, одна команда запуска |
| 18 | В логи сабмита идут только агрегаты | тексты закрытых вопросов не должны покидать платформу; подгонка под public-часть не переносится на private |
| 19 | Стиль ответа: прямой ответ первым, пункт в скобках или «Источник: …» | так написаны эталоны организаторов (24–60 слов) |
| 20 | Примеры в промпте подключаются только при наличии их документов в базе | промпт не должен упоминать документы, которых модель не видит |
| 21 | В оцениваемый ответ идёт только прямой ответ на вопрос; смежные нормы модель пишет в отдельный блок `<extra>`, который виден только в веб-чате | первый сабмит дал 0,32 при потолке около 0,5 у всех команд; наши ответы были в 1,4 раза длиннее эталонов и в 33 из 54 случаев содержали числа, которых нет в эталоне. Судья базы не видит, и верное «лишнее» для него неотличимо от выдуманного |
| 22 | Локальная оценка по умолчанию сравнивает ответ с самим эталоном в роли baseline | baseline организаторов сильный (никто не набрал 0,5); сравнение со слабым примером сабмита завышало ожидания |
| 23 | Страховочный предел длины ответа — 90 слов (140 для шагов и расчётов), хвост уходит в `<extra>`; жёсткой обрезки под длину эталона нет | второй сабмит подтвердил, что короче — лучше (+0,056), но замер на записанных ответах показал: обрезка до 60 слов теряет обязательный факт в 5 ответах из 54. Длину держит промпт, код ловит только выбросы |
| 24 | Ответ = прямой ответ + сведения того же положения, без которых он неполон (вторая половина пункта, определение срока, «предел не установлен», оговорка о применимости); прочее — в `<extra>` | локальный судья на 68 вопросах: ответы третьей версии теряли именно такие сведения из эталонов, а лишние детали («НДС 20 %», процедурные подробности) судья считал выдуманными |
| 25 | Ответ, оборванный лимитом токенов, запрашивается повторно с большим лимитом; незаконченное предложение отбрасывается. Нижняя граница `max_tokens` — 3000 | модель рассуждает перед ответом, и рассуждения расходуют лимит: на 68 вопросах 2 ответа обрывались на полуслове |
| 26 | Версии сравниваются по нескольким прогонам судьи против двух baseline — слабого (`sample`) и самого сильного (эталон); по одному прогону решения не принимаются | одна и та же версия в двух прогонах дала 0,887 и 0,816: судья обнулил 4–5 и 9–10 ответов. Пятый сабмит (0,419 после 0,449) оказался в пределах этого разброса |
| 27 | Лишнее из готового ответа вычёркивает отдельный проход, который умеет только удалять: модель называет номера фрагментов, ответ собирает код. Прямой ответ, строка источника, шаги, сведения о редакции и об отсутствии данных в базе защищены кодом | судья не видит базу и принимает верное «попутное» положение за выдумку, а модель добавляет такие положения непредсказуемо. На сохранённых ответах трёх прогонов: 0,833 → 0,877 против `sample` и 0,251 → 0,266 против эталона |
| 28 | Правило «добавь соседний пункт по той же теме» убрано | оно попадало в эталон в одном случае и давало обнуление в нескольких; с проходом вычёркивания такие добавления всё равно удаляются |
| 29 | Номера частей статей в ссылках на законы остаются, даже когда части в тексте не пронумерованы | удаление номеров ухудшило балл во всех шести замерах: точная ссылка для судьи важнее риска, что он сочтёт номер неверным |
